# cv

**履歴書・申請書に転記するための業績データを置く場所です。**

researchmap を正本とし、そこからエクスポートしたものを履歴書の様式に合わせて並べ替えたマスターをここに持ちます。非常勤講師の応募、科研費の申請、学内書類などで、同じ内容を様式ごとに書き直す手間をなくすためのものです。

[bibliography/](../bibliography/) と対になります。あちらが業績の「中身」（Zotero が正本）、こちらが業績の「一覧」（researchmap が正本）です。どちらも**外部システムが正本で、ここにあるのは転記用の派生データ**です。

## 構成

| 場所 | 中身 |
|---|---|
| `master/` | 履歴書記入用のマスターCSV。`★` を埋めて使う |
| `pending/` | researchmap にまだ登録していない追加分の置き場 |

## 使い方

1. researchmap の「業績一覧ダウンロード」で**全データ**をエクスポートし、`rm_*.csv` として
   この直下に置く（`researchers` `education` `research_experience` `published_papers` など
   20種類ほどのファイルになります。**全部置いてください**）
2. マスターを生成する（下記）
3. 残った `★` を自分で埋める
4. 履歴書の様式に合わせて `master/` から書き写す

### 2. マスターを生成する

エージェントに次のように頼みます。

```text
cv/README.md を読んで、cv/ 直下の rm_*.csv から cv/master/ を作ってください。
作成後、★ が残っている項目を一覧にしてください。
```

エージェントは次を実行します。

```bash
python3 .claude/skills/cv/researchmap_to_cv.py --dry-run   # 差分を見せる
python3 .claude/skills/cv/researchmap_to_cv.py             # 本実行
```

`master/` が、置いたエクスポートから一度に作られます。
**researchmap から埋まらないものは `★` で出ます。** `★` を検索すれば、自分で埋める
べきものだけが残ります。

| `★` が出るところ | 理由 |
|---|---|
| 本務先の郵便番号・住所・電話 | researchmap に項目がない |
| 生年月日・性別・国籍 | researchmap に**列はあるが未入力**。researchmap 側に入れれば次回から反映される |
| 学位（`03`） | 同じく列はあるが未入力。researchmap は学位を1件しか持てないので、複数あるなら手で足す |
| 種別（学/修/博）と日（`03`） | researchmap に項目がない。学位記を見て埋める |
| 専任・非常勤の別（`04`） | researchmap に項目がない。所属ごとに判断が違う |
| 所属学会の入会年月（`05`） | 列はあるが未入力。researchmap 側に入れれば次回から反映される |
| 高校・交換留学・満期退学（`02` の末尾） | researchmap に項目がない。必要なら足し、不要なら行ごと削除 |
| 掲載欄の判断（`10`） | どの欄に載せるかは自分で決める項目 |

**「項目がない」と「未入力」は区別してあります。** 前者は手で埋めるしかありませんが、後者は
researchmap に入れておけば以後ずっと自動で入ります。

**手で直したファイルは、次回の実行で上書きされません。** 生成時のハッシュを
`master/.manifest.json` に記録して照合しているためです。上書きしたいときだけ `--force`
を付けます（`master/.backup/` へ退避されます）。

### 新しい業績を1件足すとき

researchmap にまだ登録していない発表や論文は、`/cv` スキルを使います。
詳しくは [pending/README.md](./pending/README.md) と
`.claude/skills/cv/SKILL.md` を参照してください。

```
/cv --add <成果物のフォルダ名>
```

**成果物のフォルダに `meta.md` を置いておくと、ほぼ全項目が自動で入ります。**
researchmap の列名で「`列名: 値`」と1行ずつ書くだけです。雛形は
[work/dihuco_workshop/drafts/sample_slide/meta.md](../work/dihuco_workshop/drafts/sample_slide/meta.md)
にあります。

```
タイトル(日本語): サンプル発表
講演者(日本語): 山田 太郎; 佐藤 花子
会議名(日本語): サンプル学会2026年度大会
発表年月日: 2026-10-05
会議種別: oral_presentation
招待の有無: 無
```

真偽値は `有` / `無`、複数人は `;` 区切り（日本語名は姓と名を空白で分ける）。
行頭 `#` はコメントです。列名の一覧は次で出せます。

```bash
python3 .claude/skills/cv/cv.py header --table presentations
```

`meta.md` が無くてもエージェントが散文から提案しますが、**項目ごとに確認が入るので時間が
かかります。** 繰り返し発表するなら `meta.md` を書いておくほうが速く、次回も使えます。

`cv/pending/pending_<table>.csv` に1行追記され、同時に `master/` にも反映されます。
**この CSV はそのまま researchmap にアップロードできる書式**なので、登録前から履歴書に使えます。

`master/` の `01`〜`10` は、大学の非常勤講師用履歴書によくある項目立てに対応させてあります。
様式が違っても、同じマスターから転記できます。**UTF-8 BOM付きなので Excel でそのまま開けます。**

| ファイル | 対応する欄 |
|---|---|
| `01_基本情報.csv` | 氏名・生年月日・国籍・連絡先 |
| `02_学歴.csv` | 学歴 |
| `03_学位.csv` | 学位 |
| `04_職歴.csv` | 職歴（常勤・非常勤を一本化） |
| `05_所属学会.csv` | 所属学会 |
| `06_専門分野.csv` | 専門分野 |
| `07_学術論文.csv` | 学術論文 |
| `08_著書・翻訳.csv` | 著書・翻訳 |
| `09_講演・口頭発表.csv` | 学会における講演、口頭発表 |
| `10_その他（掲載欄の判断用）.csv` | 様式外。書評・翻訳・連載をどの欄に載せるかの判断用 |

`11` 以降は履歴書の様式には無いことが多い業績ですが、**科研費の業績報告や別紙での提出で
求められる**ため、researchmap が持っているものはすべて出します。

| ファイル | 中身 |
|---|---|
| `11_受賞.csv` | 受賞歴 |
| `12_研究課題.csv` | 研究課題。制度名・研究種目・課題番号・配分額を含む |
| `13_委員歴.csv` | 委員歴 |
| `14_社会貢献・学術貢献.csv` | 社会貢献と学術貢献を1本にまとめたもの |
| `15_メディア報道.csv` | メディア報道 |
| `16_作品.csv` | 作品等 |
| `17_産業財産権.csv` | 産業財産権 |
| `18_その他.csv` | その他 |

**researchmap に登録がないテーブルはファイルを作りません。** 実行の最後に「生成しなかったもの」
として一覧で出るので、登録漏れかどうかはそこで分かります。

### 「（参考）」付きの列

様式に欄がないことが多い項目です。査読の有無・招待の有無・国際共著・配分額・DOI などで、
**別紙や科研費の報告で求められるもの**を落とさないために列として持たせてあります。
様式に欄がなければ転記時に無視してください。

**エクスポートが持っている値はメモ欄に畳まず、必ず列にする**方針です。CSVの時点で構造化
されているものを散文に戻すと、後から機械で拾えなくなるためです。真偽値は `有`／`無`／空欄の
3状態で出ます。**空欄と `無` は意味が違います**（researchmap に未入力か、否と登録したか）。

## 記入のルール

- **`★` が入力すべきセル。** 全ファイルを `★` で検索すれば残りの作業量が分かる
- **`メモ` 列は転記時の注意書き。** 履歴書には転記しない
- **提出日によって変わる項目は空欄のまま残す**（作成日・満年齢など）
- **継続中の職・学会は `至` に `～現在` と書く**
- 様式が学歴・学位・職歴に「日」列を求めることがある。学位記や辞令で確認する

## 基本情報の扱い（重要）

**`01_基本情報.csv` は `.gitignore` で除外してあります。** 生年月日・住所・電話番号を
入れる場所なので、既定では追跡しません。使うときは雛形をコピーしてください。

```bash
cp cv/master/01_基本情報.csv.example cv/master/01_基本情報.csv
```

雛形の連絡先欄は**本務先だけ**にしてあります。現住所や自宅の電話番号は、マスターに持たず
**提出のたびに直接入力してください。** 本務先の住所・電話は変わらないので持たせて構いません。

### ここに書かないもの

次は、private リポジトリであっても**決して書かないでください。**

- **自宅住所、自宅・携帯の電話番号**
- **パスポート番号、マイナンバー、運転免許証番号、基礎年金番号**
- 銀行口座、クレジットカード番号
- 本人確認書類の画像

理由は2つあります。第一に、**AIエージェントは工房の中を読みます。** ここに書いたものは、
プロンプトに貼らなくても読まれて開発元のサーバへ送られうる範囲に入ります。第二に、
**git は消しても履歴に残ります。** 一度コミットすると、後から削除しても過去の版から読めます。

履歴書の様式がこれらを求める場合は、**提出用のファイルにだけ手で書き込み、リポジトリには戻さない**運用にしてください。

このリポジトリを private で使っていても、**公開リポジトリへ転記・コピーしないよう注意してください。**

## 複数のリポジトリを持つようになったら

CV は**研究目的ではなく研究者本人に属する**ものです。このリポジトリを終了しても、
別のテーマで新しいリポジトリを作っても、CV は付いて回ります。

そのため、研究リポジトリを複数持つようになったら、**`cv/` はこのリポジトリの外に出してください。**
個人用のリポジトリを1つ作るか、`repos/` に独立したリポジトリとして置くのが自然です。

ここに置いているのは、最初のうち1つのフォルダで完結させるためです。
