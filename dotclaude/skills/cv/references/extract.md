# 成果物のどこを見るか / 必ず確認する項目

## 自動で拾える（`cv.py extract --table <table>`）

キー付きで書かれている文字列だけを機械抽出する。散文は拾わない。

### `meta.md`（最優先・これが主役）

成果物のフォルダに `meta.md` を置くと、**researchmap の列名で書かれた項目を全部そのまま拾う。**
`--table` で指定したテーブルの列であれば、何項目でも拾える。

```
タイトル(日本語): サンプル発表
講演者(日本語): 山田 太郎; 佐藤 花子
会議名(日本語): サンプル学会2026年度大会
発表年月日: 2026-10-05
会議種別: oral_presentation
招待の有無: 無
```

| きまり | 内容 |
|---|---|
| 列名 | researchmap の項目名そのまま。一覧は `cv.py header --table <table>` で出る |
| コメント | 行頭 `#` は無視する。雛形の説明文を残したまま使える |
| 真偽値 | `有` / `無`（`あり` `なし` `はい` `いいえ` `TRUE` `FALSE` も可）→ `TRUE`/`FALSE` に直る |
| 複数人 | `;` で区切る。日本語名は姓と名を空白で分ける（`山田 太郎` → `[山田\,太郎]`） |
| 未記入 | 行ごと消す。空で残すと未記入のまま扱う |

**`meta.md` に書いた値が他の出所より優先される。**

### `abstract.md` と `main.tex`（`meta.md` に無い項目の補完）

| 項目 | 出所 |
|---|---|
| タイトル(英語) | `<key>/abstract/abstract.md` の `TITLE:`（`<br>` は空白に戻す）。無ければ `<key>/manuscript/main.tex` の `\title{}` |
| 講演者(英語) / 著者(英語) | 同 `AUTHORS:` をカンマ分割。`YAMADA` のような全大文字の姓は `Yamada` に戻す |
| 概要(英語) | `abstract.md` の `---` 以降の本文。改行を空白に畳む |

`abstract.md` の `KEY: value` ヘッダ＋`---`＋本文という規約は `/build-abstract` が作る形。
この階層（`abstract/` `manuscript/`）を持たない構成なら、`meta.md` だけで足りる。

### 既定値で埋まるもの

`公開の有無` = `disclosed`、`主要な業績かどうか` = `FALSE`。毎回聞かない。

## 成果物を探す場所

`<key>` は次の順で探す。見つかった全てを読み、先に見つかった値を使う。

| 探す場所 |
|---|
| `publications/<key>/` |
| `work/*/drafts/<key>/` |
| `work/*/drafts/*/<key>/` |
| `<key>` がそのままディレクトリのパスであればそれ |

## Claude が読んで提案する

**`meta.md` に書かれていない項目だけが対象。** `extract` の返り値 `unresolved` がその一覧で、
`meta_template` にはそのテーブルの全列名が入っている。`meta.md` が無い成果物では
**まず `meta_template` を使って `meta.md` の雛形を作り、PI に埋めてもらうほうが早い。**
毎回ゼロから聞き取るより、次回以降も再利用できる。

残った項目は `context_files`（`README.md`、`manuscript/main_ja.md`）を Read して、
**提案値を添えて** PI に確認する。散文なので機械抽出しない。

| 項目 | 読み取り先と注意 |
|---|---|
| 会議名 | README の投稿情報節。正式名称かどうかを確認する |
| 開催年月日(From/To) | README の会期。発表日とは別物 |
| 開催地 / 国・地域 | README の開催都市。国はISO alpha-3 に直す |
| タイトル(日本語) | `main_ja.md` の H1。**Marp スライドの frontmatter `title:` は使わない**（スライド用の略称で正式題目と一致しない実例がある） |
| 著者(日本語) | 英語名からの推定は誤りやすい。共著者は PI に確認する |

## 必ず PI に確認する

既定値を添えて聞く。黙って埋めない。

| 項目 | 既定の提案 |
|---|---|
| 発表年月日 | なし。**会期からは決まらない。** リポジトリに記録がないことが多い |
| 会議種別 | `oral_presentation` |
| 招待の有無 | `FALSE` |
| 記述言語 | 発表言語。国際会議なら `eng` |
| 国際・国内会議 | 国外開催なら `TRUE` |
| 国際共著 | 全著者が国内機関なら `FALSE` |
| 主催者 | なし。**分からなければ `null`。** 推測で埋めない |
| URL | なし。README にある登録URLは会議URLではないので取り違えない |
| 査読の有無（論文） | 掲載後に確認 |
| 誌名・巻・号・ページ・DOI | 刊行後。未確定なら `forthcoming.md` で待つ |

## 著者名の表記

| 言語 | 形式 | 例 |
|---|---|---|
| 日本語 | 姓名をエスケープカンマで分ける | `[山田\,太郎,佐藤\,花子,鈴木\,一郎]` |
| 英語 | 空白区切り・エスケープなし | `[Taro Yamada,Hanako Sato]` |

改姓している場合、旧姓の既存レコードは当時の事実なので書き換えない。新規は常に現姓で書く。
自分の表記は `cv.py` の `SELF_ALIASES` に書いておく（旧姓も入れる。判定にだけ使う）。

## 国際学会での英語発表

英語で発表したものは、**日本語欄も英語表記に揃える**方針にしておくと一貫する。`タイトル(日本語)` に英語題目、
`講演者(日本語)` に英語氏名を入れ、日英を同じ値にする。日本語欄を `null` にする手もあるが、
どちらかに決めて通すこと。混在すると後から一覧を作るときに揃えなおす手間が出る。

日本語題目しか持たない発表（国内学会）は従来どおり日本語欄に日本語を書く。
`開催地` は日英それぞれの表記でよい（`東京` / `Tokyo`）。

## 固定値

`主要な業績かどうか` = `FALSE`、`公開の有無` = `disclosed`（既存レコードに合わせる）。
